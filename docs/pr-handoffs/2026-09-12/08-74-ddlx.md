## 不能直接移植的部分

参考是受控“创建”适配器，并没有证明 issue 所需的通用 update/upsert 已全部存在。TS 普通 AbapChangeWorkflow resolver 仅覆盖四类 ABAP source object，不能把 DDLX 直接路由过去。它的计划/确认/profile、固定验证环境和类型注册不属于 Go 本次必需范围。

## Go 分阶段方案

1. 先复核维护者偏好：复用 GetSource/WriteSource 的统一入口，还是原 issue 的 WriteMetadataExtension。倾向统一入口；若新增专用工具，保持现有模式注册一致，避免重复能力。
2. 实现 DDLX 类型常量、URL、创建 XML/媒体类型、只读 source 访问。
3. 在统一 writer 的 create/update/upsert 中接入；创建要求必要包，更新解析已有对象。依赖 #143 未合并时明确处理相邻 gate，不能绕过。
4. DDLS 引用必须是预期 active 对象；source 中 annotate 的对象应与声明一致，支持 view/entity 形态按真实协议与测试收敛，不用过窄 regex 宣称全 ABAP 语法。
5. 生命周期：预检/包和传输策略 → create 或已有对象 → LOCK → PUT → 语法检查 → UNLOCK → activate → active 读回。
6. 新增 enum/help/router/模式测试；不得只加底层方法却让 MCP 不可达。
7. 不混入 DCLS、DDLA、Fiori 页面、OData 发布或批量对象创建。
